## しくみ

ファイルを**オブジェクト**として、**バケット**という入れ物に保存します。オブジェクトは「キー（名前）＋データ＋メタデータ」で、HTTPS の API で読み書きします。

- 容量は無制限。1 つのオブジェクトは最大 5 TB（大きいファイルはマルチパートアップロード）
- データはリージョン内の**複数の AZ**に自動で保存される（1 ゾーン型のクラスを除く）
- バケット名は世界中で一意。バケットはリージョンを選んで作る

## ストレージクラス（頻出）

| クラス | 向いているデータ | 特徴 |
|---|---|---|
| S3 Standard | よく読むデータ | 標準。取り出し料金なし |
| S3 Intelligent-Tiering | アクセス頻度が**分からない・変わる** | 使われ方を見て自動で安い層へ移す |
| S3 Standard-IA | たまにしか読まないが、すぐ読みたい | 保存は安く、取り出しに料金がかかる |
| S3 One Zone-IA | 再作成できる、たまに読むデータ | 1 つの AZ だけに保存。さらに安い |
| S3 Glacier Instant Retrieval | ほぼ読まないが、読むときはすぐ | ミリ秒で取り出せるアーカイブ |
| S3 Glacier Flexible Retrieval | 年に数回読むアーカイブ | 取り出しに数分〜数時間 |
| S3 Glacier Deep Archive | 長期保管（7〜10 年など） | 最安。取り出しに 12 時間程度 |

詳しくは [[s3-glacier]]。

## 主な機能

- **ライフサイクルポリシー**：「30 日たったら Standard-IA へ、1 年で Deep Archive へ、7 年で削除」のように自動で移動・削除
- **バージョニング**：上書きや削除をしても前の版を残す。誤削除の対策
- **レプリケーション**：別のリージョン（CRR）や同じリージョンの別バケット（SRR）へ自動でコピー。バージョニングが必要
- **暗号化**：標準で SSE-S3 が有効。鍵を管理したいなら SSE-KMS（[[kms]]）
- **アクセス制御**：バケットポリシー、IAM ポリシー、**ブロックパブリックアクセス**
- **署名付き URL**：期限付きで、特定のオブジェクトへのアクセスを許可する
- **アクセスポイント**：1 つのバケットに用途ごとの入口を作り、それぞれにポリシーを付ける（[[s3-access-points]]）
- **オブジェクトロック**：一定期間、削除・上書きを禁止する（WORM。コンプライアンス対策）
- **静的 Web サイトホスティング**、**Transfer Acceleration**（遠くからのアップロードを高速化）、**イベント通知**

## 試験でのポイント

- 「静的コンテンツ」「画像・動画の保存」「データレイク」「バックアップの保存先」→ S3
- アクセス頻度が予測できない → **Intelligent-Tiering**
- 世界中に配信するなら [[cloudfront]] と組み合わせ、**OAC** で S3 へ直接アクセスさせない
- VPC 内から S3 へインターネットを通らずにアクセス → **ゲートウェイ型の [[vpc-endpoint]]**（無料）
- 誤削除対策 → バージョニング＋ MFA 削除

## よくあるひっかけ

- S3 は OS からディスクとしてマウントするものではない。共有ファイルシステムが必要なら [[efs]] や [[fsx]]
- Standard-IA などには**最低保存期間**（30 日など）と取り出し料金がある。頻繁に読むデータを置くと逆に高くなる
- One Zone-IA は AZ の障害でデータを失う可能性がある。再作成できないデータには使わない
