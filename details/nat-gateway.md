## しくみ

プライベートサブネットのインスタンスが、**外からは接続されないまま**、インターネットへ通信できるようにします（パッチやパッケージのダウンロードなど）。

- **パブリックサブネット**に作り、Elastic IP を割り当てる
- プライベートサブネットのルートテーブルに `0.0.0.0/0 → NAT ゲートウェイ` の経路を書く
- AWS がマネージドで運用し、帯域は自動でスケールする（最大 100 Gbps 程度）
- 料金：時間あたりの料金＋処理したデータ量

## 高可用性（頻出）

- NAT ゲートウェイは **1 つの AZ の中**で冗長化されている。AZ が丸ごと落ちると使えなくなる
- 高可用性にするには、**AZ ごとに 1 つずつ** NAT ゲートウェイを作り、各 AZ のプライベートサブネットは同じ AZ の NAT ゲートウェイを使う

## NAT インスタンスとの違い

| 項目 | NAT ゲートウェイ | NAT インスタンス（EC2 で自作） |
|---|---|---|
| 管理 | AWS がマネージド | 自分でパッチ・冗長化 |
| 可用性 | AZ 内で冗長 | 自分でスクリプトなどを用意 |
| セキュリティグループ | 付けられない | 付けられる |

## 試験でのポイント

- 「プライベートサブネットからインターネットへ（外向きのみ）」→ NAT ゲートウェイ
- 「S3 や DynamoDB へのアクセスのデータ転送料を減らしたい」→ NAT ゲートウェイを通さず、**ゲートウェイ型の [[vpc-endpoint]]**（無料）

## よくあるひっかけ

- NAT ゲートウェイをプライベートサブネットに置くのは誤り（外へ出られない）
- インターネットから内部のサーバーへ接続させる用途には使えない。それは [[elb]] などを使う
