## しくみ

データベースを AWS へ移行するサービスです。**移行中も元のデータベース（ソース）は動いたまま**で、変更を移行先（ターゲット）へ反映し続けられるので、停止時間を最小にできます。

- **レプリケーションインスタンス**（またはサーバーレス）が、ソースからデータを読んでターゲットに書き込む
- 移行の種類：**全ロード**、**変更データキャプチャ（CDC）**による継続的な複製、その両方
- **同種間の移行**（Oracle → RDS for Oracle）も、**異種間の移行**（Oracle → Aurora PostgreSQL）もできる
- **異種間**の場合は、テーブル定義などのスキーマを **AWS SCT（Schema Conversion Tool）** や DMS Schema Conversion で変換する
- ソース・ターゲットの例：オンプレミスの DB、[[rds]]、[[aurora]]、[[redshift]]、[[dynamodb]]、[[s3]]、[[documentdb]]

## 試験でのポイント

- 「DB を最小の停止時間で AWS へ移行」「移行中もアプリを動かしたい」→ DMS
- 「Oracle / SQL Server から Aurora などへ、エンジンを変えて移行」→ **SCT でスキーマ変換＋DMS でデータ移行**
- 「オンプレミスの DB から AWS へ継続的にデータを複製」→ DMS の CDC

## よくあるひっかけ

- 同種間の移行では、スキーマの変換（SCT）は不要
- データ量が非常に多く、回線では時間がかかりすぎるときは、[[snow-family]] でまとめて送ってから、差分を DMS で同期する方法もある
