## しくみ

受け取った通信を、複数の**ターゲット**（EC2、コンテナ、IP アドレス、Lambda など）に振り分けます。**ヘルスチェック**で異常なターゲットを外すので、1 台が壊れてもサービスを続けられます。複数の AZ に配置して使います。

## 種類（頻出）

| 種類 | 層 | 特徴 | 試験でこう出たら |
|---|---|---|---|
| **Application Load Balancer（ALB）** | L7（HTTP/HTTPS） | **パス**（`/api/*`）や**ホスト名**、ヘッダーで振り分け。Lambda もターゲットにできる。WAF と連携 | 「パスベースのルーティング」「マイクロサービス」「HTTP ヘッダーで振り分け」 |
| **Network Load Balancer（NLB）** | L4（TCP/UDP/TLS） | 超低レイテンシー、大量の通信。**AZ ごとに固定 IP**（Elastic IP も可） | 「固定 IP」「TCP/UDP」「毎秒数百万リクエスト」 |
| **Gateway Load Balancer（GWLB）** | L3 | ファイアウォールなどのセキュリティ機器（仮想アプライアンス）に通信を通す | 「サードパーティの仮想ファイアウォールを透過的に挟む」 |
| Classic Load Balancer | L4/L7 | 旧世代 | 新規では使わない |

## 主な機能

- **SSL/TLS の終端**：[[acm]] の証明書を ELB に設定し、暗号化の処理を ELB に任せる
- **スティッキーセッション**：同じ利用者を同じターゲットに送り続ける
- **Connection Draining（登録解除の遅延）**：外すターゲットの処理中のリクエストが終わるまで待つ
- **クロスゾーン負荷分散**：AZ をまたいで均等に振り分ける
- [[ec2-auto-scaling]] と組み合わせて、増えたインスタンスを自動で登録する

## 試験でのポイント

- 「URL のパスで別々のサービスへ」→ **ALB**
- 「クライアントが IP アドレスを許可リストに登録する必要がある」→ **NLB**（固定 IP）か [[global-accelerator]]
- ALB の後ろのサーバーで利用者の IP アドレスを知りたい → **X-Forwarded-For** ヘッダー

## よくあるひっかけ

- ALB は固定 IP を持たない（IP アドレスが変わる）。固定 IP が必要なら NLB
- ELB は 1 つのリージョンの中で振り分ける。リージョンをまたいだ振り分けは [[route53]] や [[global-accelerator]]
