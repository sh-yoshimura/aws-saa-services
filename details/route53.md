## しくみ

ドメイン名（`example.com`）を IP アドレスや AWS のリソースに変換する **DNS サービス**です。SLA 100% の高い可用性があります。

- **ドメインの登録**ができる
- **ホストゾーン**：ドメインのレコードの入れ物。パブリック（インターネット向け）とプライベート（VPC 内向け）がある
- **ヘルスチェック**：エンドポイントの正常・異常を監視し、ルーティングに使う

## レコードの種類

- **A / AAAA**：名前 → IPv4 / IPv6 アドレス
- **CNAME**：名前 → 別の名前（**ドメインの頂点（`example.com`）には使えない**）
- **エイリアスレコード**：名前 → AWS のリソース（ELB、CloudFront、S3 の静的サイトなど）。**頂点にも使え、問い合わせは無料**

## ルーティングポリシー（頻出）

| ポリシー | 動き | 試験でこう出たら |
|---|---|---|
| シンプル | 1 つの宛先に送る | — |
| **フェイルオーバー** | 正常ならプライマリ、異常ならセカンダリ | 「障害時に別のリージョン／静的サイトへ切り替え」（アクティブ／パッシブ） |
| **加重** | 決めた割合で振り分け（例 90:10） | 「新バージョンに一部の通信だけ流す」 |
| **レイテンシー** | 利用者から最も遅延が少ないリージョンへ | 「世界中の利用者に最速の応答」 |
| **位置情報** | 利用者の国・大陸で振り分け | 「国ごとにコンテンツを変える」「特定の国だけに配信」 |
| 地理的近接性 | 距離で振り分け、バイアスで範囲を調整 | 「振り分ける範囲を調整したい」 |
| 複数値回答 | 正常な複数の IP を返す | 「簡易的な負荷分散」 |
| IP ベース | 利用者の IP アドレスの範囲で振り分け | — |

## 試験でのポイント

- 「リージョン障害時に、別のリージョンへ自動で切り替え」→ **フェイルオーバールーティング＋ヘルスチェック**
- `example.com` を ELB や CloudFront に向ける → **エイリアスレコード**
- オンプレミスと VPC の間で名前解決 → **Route 53 Resolver**（インバウンド／アウトバウンドエンドポイント）

## よくあるひっかけ

- 位置情報ルーティング（利用者の場所）とレイテンシールーティング（速さ）を取り違えやすい
- DNS は TTL の間キャッシュされるので、切り替えはすぐには反映されない。即時の切り替えが必要なら [[global-accelerator]]
