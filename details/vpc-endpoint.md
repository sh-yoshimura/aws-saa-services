## しくみ

VPC の中から、**インターネットや NAT ゲートウェイを通らずに** AWS のサービスへ接続するための入口です。通信は AWS のネットワーク内で完結します。

| 種類 | 対象 | しくみ | 料金 |
|---|---|---|---|
| **ゲートウェイエンドポイント** | **S3 と DynamoDB だけ** | ルートテーブルに経路を追加する | **無料** |
| **インターフェイスエンドポイント**（AWS PrivateLink） | 多くの AWS サービス、他社や自社のサービス | サブネットにプライベート IP 付きの ENI を作る | 時間＋データ量 |

- **エンドポイントポリシー**で、エンドポイント経由でアクセスできるリソースを制限できる
- S3 のバケットポリシーで「特定のエンドポイントからのアクセスだけ許可」（`aws:SourceVpce`）とすることもできる

## AWS PrivateLink

インターフェイスエンドポイントのしくみを使うと、**自分の VPC にあるサービス**（NLB の後ろ）を、別の VPC や別のアカウントに、VPC ピアリングなしで公開できます。

## 試験でのポイント

- 「プライベートサブネットから S3 へ、インターネットを経由せずに」→ **ゲートウェイエンドポイント**
- 「NAT ゲートウェイのデータ処理料金を減らしたい（S3 への大量転送）」→ **ゲートウェイエンドポイント**
- 「プライベートサブネットから Systems Manager・Secrets Manager・ECR などを使いたい」→ **インターフェイスエンドポイント**
- 「自社のサービスを、他のアカウントの VPC に非公開で提供したい」→ **PrivateLink**

## よくあるひっかけ

- オンプレミスから（Direct Connect や VPN 経由で）S3 に非公開で接続したい場合、ゲートウェイエンドポイントは使えない。**インターフェイスエンドポイント**を使う
