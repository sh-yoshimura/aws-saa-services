## しくみ

アプリのコード（Java、Python、Node.js、PHP、Docker など）をアップロードするだけで、動かすための環境を自動で作ります。裏では次のようなリソースが作られます。

- [[ec2]] インスタンス、[[ec2-auto-scaling]] グループ、[[elb]]、セキュリティグループ
- 監視（[[cloudwatch]]）やログの収集

作られたリソースは自分のアカウントにあるので、細かい設定を後から変えることもできます。

## 環境の種類

| 種類 | 内容 |
|---|---|
| Web サーバー環境 | ELB + Auto Scaling で HTTP リクエストを処理する |
| ワーカー環境 | [[sqs]] のキューからメッセージを受け取ってバックグラウンド処理をする |

## デプロイ方式

| 方式 | 特徴 |
|---|---|
| 一度に全部（All at once） | 最速だが、デプロイ中は停止する |
| ローリング | 少しずつ入れ替える。その間は処理能力が下がる |
| 追加バッチ付きローリング | 先に台数を増やしてから入れ替えるので、処理能力を保てる |
| イミュータブル | 新しいインスタンス群を別に作って入れ替える。失敗時の戻しが速い |
| ブルー／グリーン | 環境ごと複製し、URL（CNAME）を切り替える |

## 試験でのポイント

- 「インフラを管理せずに、Web アプリを素早くデプロイしたい」「開発者がコードに集中したい」→ Elastic Beanstalk
- Elastic Beanstalk 自体は無料。作られた EC2 などの料金がかかる
- 本番 DB は環境の外に [[rds]] として作るのがおすすめ（環境を削除すると、環境内の DB も消えるため）

## よくあるひっかけ

- インフラ全体をテンプレートで細かく定義・再現したいなら [[cloudformation]] のほうが合う
- コンテナを本格的に運用するなら [[ecs]] や [[eks]]
