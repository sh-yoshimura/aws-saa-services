## しくみ

オープンソースの**メッセージブローカー**（**Apache ActiveMQ** と **RabbitMQ**）を、AWS がマネージドで提供します。業界標準のプロトコルや API に対応しているので、既存のアプリをほとんど変えずに移行できます。

- 対応する API・プロトコル：JMS、AMQP、MQTT、OpenWire、STOMP、WebSocket
- **アクティブ／スタンバイ構成**で、別の AZ に待機系を置ける（高可用性）
- ブローカー（インスタンス）単位で動くので、スケールには上限がある

## SQS / SNS との違い

| 項目 | Amazon MQ | [[sqs]] / [[sns]] |
|---|---|---|
| プロトコル | **業界標準**（JMS、AMQP、MQTT など） | AWS 独自の API |
| スケール | ブローカーのサイズに依存 | ほぼ無制限、サーバーレス |
| 向いている場面 | **既存のアプリの移行** | 新しく作るアプリ |

## 試験でのポイント

- 「オンプレミスの ActiveMQ / RabbitMQ を移行」「アプリのコードを書き換えずに」「JMS」「MQTT」→ Amazon MQ

## よくあるひっかけ

- 新しく作るクラウドネイティブなアプリで Amazon MQ を選ぶのは誤りになりやすい。運用が楽でスケールする SQS / SNS を選ぶ
