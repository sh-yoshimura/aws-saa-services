## しくみ

AWS のリージョンの中に作る、**自分専用の仮想ネットワーク**です。IP アドレスの範囲（CIDR、例 `10.0.0.0/16`）を決めて作り、その中を**サブネット**に分けます。

- **サブネット**：1 つの **AZ** の中に作る。CIDR の一部（例 `10.0.1.0/24`）を割り当てる
  - **パブリックサブネット**：ルートテーブルに [[internet-gateway]] への経路がある
  - **プライベートサブネット**：インターネットへの直接の経路がない
- **ルートテーブル**：サブネットからの通信をどこへ送るかを決める
- 各サブネットの先頭 4 つと最後の 1 つの IP アドレスは AWS が予約している（使えるのは 5 つ少ない）

## セキュリティグループとネットワーク ACL（頻出）

| 項目 | セキュリティグループ | ネットワーク ACL |
|---|---|---|
| 適用先 | インスタンス（ENI）単位 | サブネット単位 |
| ルール | **許可のみ** | 許可と**拒否** |
| 状態 | **ステートフル**（戻りの通信は自動で許可） | **ステートレス**（戻りの通信も許可が必要） |
| 評価 | すべてのルールを評価 | ルール番号の小さい順に評価 |

## 他のネットワークとつなぐ方法

| 方法 | つなぐ先 |
|---|---|
| [[internet-gateway]] | インターネット（双方向） |
| [[nat-gateway]] | インターネット（プライベートサブネットから外向きのみ） |
| [[vpc-endpoint]] | S3 などの AWS サービス（インターネットを通らない） |
| **VPC ピアリング** | 別の VPC と 1 対 1 で接続（推移的なルーティングはできない） |
| [[transit-gateway]] | 多数の VPC・オンプレミスをハブで接続 |
| [[site-to-site-vpn]] / [[direct-connect]] | オンプレミス |

## 監視

- **VPC フローログ**：ネットワークインターフェイスを通った通信の記録（許可・拒否）を [[cloudwatch]] Logs や [[s3]] に保存する

## 試験でのポイント

- 高可用性のため、サブネットは**複数の AZ**に作る（Web 層・DB 層それぞれ）
- 「特定の IP アドレスからの通信を拒否したい」→ **ネットワーク ACL**（セキュリティグループは拒否できない）
- 「通信が届かない原因を調べたい」→ **VPC フローログ**
- VPC ピアリングは CIDR が重なっていると接続できない

## よくあるひっかけ

- A–B、B–C がピアリングしていても、A から C へは通信できない（推移しない）。多数をつなぐなら Transit Gateway
- ネットワーク ACL はステートレスなので、戻りの通信（エフェメラルポート 1024–65535 など）の許可を忘れると通信できない
