## しくみ

ストリーミングデータを受け取り、**保存先へ自動で届ける**サービスです（旧 Kinesis Data Firehose）。シャードなどの容量の管理は不要で、自動でスケールします。

- 保存先：[[s3]]、[[redshift]]（S3 経由）、[[opensearch]]、Splunk、Datadog などの HTTP エンドポイント
- データを**バッファ**（一定のサイズか時間でまとめて）してから届けるので、**ニアリアルタイム**（数十秒〜数分の遅れ）
- 途中で [[lambda]] を使ってデータを変換できる。**Parquet / ORC への変換**や圧縮もできる
- 送信元：アプリから直接、[[kinesis-data-streams]]、[[cloudwatch]] Logs、[[sns]] など

## Data Streams との違い

| 項目 | [[kinesis-data-streams]] | Data Firehose |
|---|---|---|
| 遅れ | リアルタイム（ミリ秒〜秒） | ニアリアルタイム（バッファ分） |
| 容量の管理 | シャード（オンデマンドも可） | 不要 |
| データの保持・再処理 | できる（最大 365 日） | できない（届けるだけ） |
| 読み取り | 自分でアプリを書く | 決まった保存先に届ける |

## 試験でのポイント

- 「ストリーミングデータを S3 / Redshift に保存」「最小の運用負荷」「ニアリアルタイムでよい」→ Data Firehose
- 「保存する前に Parquet に変換したい」→ Data Firehose のデータ形式変換

## よくあるひっかけ

- 「リアルタイムに（すぐに）処理したい」「複数のアプリで読みたい」なら Data Streams
