## しくみ

多数の VPC やオンプレミスのネットワークを、**中心の 1 か所（ハブ）**につなぐことで、まとめて相互接続できるようにするサービスです（ハブアンドスポーク型）。

- 接続できるもの：VPC、[[site-to-site-vpn]]、[[direct-connect]]（Direct Connect ゲートウェイ経由）、別のリージョンの Transit Gateway（ピアリング）
- **ルートテーブル**で、どこからどこへの通信を許すかを分けられる（本番と開発を分離するなど）
- [[organizations]] と Resource Access Manager で、他のアカウントと共有できる
- VPN の **ECMP**（複数のトンネルを束ねる）で、帯域を増やせる

## VPC ピアリングとの違い

| 項目 | VPC ピアリング | Transit Gateway |
|---|---|---|
| つなぎ方 | 1 対 1（メッシュ） | ハブアンドスポーク |
| 推移的なルーティング | できない | **できる** |
| 向いている規模 | 少数の VPC | **多数の VPC** |
| 料金 | 接続自体は無料（データ転送料のみ） | 接続ごとの時間料金＋データ処理料 |

## 試験でのポイント

- 「数十〜数百の VPC を接続」「ピアリングの管理が複雑」「オンプレミスとも共通で接続」→ Transit Gateway
- 「2 つの VPC をつなぐだけ」「最もコストが低い」→ VPC ピアリング

## よくあるひっかけ

- 少数の VPC で Transit Gateway を選ぶと、コスト面で VPC ピアリングに負けることがある
