## しくみ

AWS が設計したサーバーラック（またはサーバー）を**自社のデータセンターに設置**し、AWS が保守します。オンプレミスにありながら、AWS のリージョンと同じ API・コンソール・ツールで操作できます。

- 使えるサービスの例：[[ec2]]、[[ebs]]、[[ecs]]、[[eks]]、[[rds]]、S3 on Outposts
- 親となる AWS リージョンとネットワークでつながっている必要がある

## 似たサービスとの違い

| サービス | 置き場所 | 目的 |
|---|---|---|
| Outposts | 自社のデータセンター | データを社内に置いたまま AWS サービスを使う |
| Local Zones | 大都市の近くにある AWS の拠点 | 利用者の近くで低レイテンシー |
| Wavelength | 通信事業者の 5G 網の中 | モバイル向けの超低レイテンシー |

## 試験でのポイント

- 「データを社外に出せない（データの所在の規制）」「工場の機器と低レイテンシーで処理したい」かつ「AWS と同じツールで運用したい」→ Outposts

## よくあるひっかけ

- オンプレミスのデータを AWS に**移す**話なら、[[datasync]] や [[snow-family]] などの移行サービス
- オンプレミスから AWS のストレージを**使う**だけなら [[storage-gateway]]
