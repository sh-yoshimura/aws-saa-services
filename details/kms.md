## しくみ

データを暗号化するための**鍵**を作成・管理するサービスです。鍵は AWS が管理する HSM（専用のハードウェア）の中に保管され、外に取り出せません。[[s3]]、[[ebs]]、[[rds]]、[[dynamodb]] など多くのサービスと連携します。

| 鍵の種類 | 管理者 | 特徴 |
|---|---|---|
| AWS 所有のキー | AWS | 利用者からは見えない。無料 |
| AWS マネージドキー | AWS | `aws/s3` のように、サービスごとに自動で作られる。ローテーションは自動 |
| **カスタマーマネージドキー** | 利用者 | **キーポリシー**で誰が使えるかを細かく決められる。自動ローテーションを設定できる。無効化・削除も可能 |

- **エンベロープ暗号化**：データはデータキーで暗号化し、データキーを KMS の鍵で暗号化する（大きなデータも暗号化できる）
- 鍵の利用は [[cloudtrail]] にすべて記録される
- **マルチリージョンキー**：同じ鍵を別のリージョンでも使える
- 鍵は**リージョン単位**。別のリージョンにスナップショットをコピーするときは、コピー先の鍵で暗号化し直す

## 試験でのポイント

- 「保管時の暗号化」「鍵の利用を監査したい」「鍵のアクセス権を管理したい」→ KMS（カスタマーマネージドキー）
- 「鍵を毎年自動でローテーション」→ カスタマーマネージドキーの自動ローテーション
- S3 で KMS を使う暗号化は **SSE-KMS**

## よくあるひっかけ

- 「鍵を専有のハードウェアで、顧客だけが管理する必要がある（FIPS 140-2 レベル 3 で、AWS も操作できない）」なら [[cloudhsm]]
- 鍵を削除すると、その鍵で暗号化したデータは二度と復号できない。削除には 7〜30 日の待機期間がある
