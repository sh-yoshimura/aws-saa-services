## しくみ

AWS のデータセンターにある物理サーバーを仮想的に分けて、1 台分のサーバー（**インスタンス**）として貸し出すサービスです。起動するときに次の 3 つを選びます。

- **AMI**：OS やソフトウェアが入ったひな形（Amazon Linux、Windows など）
- **インスタンスタイプ**：CPU・メモリの大きさ（例 `t3.micro`、`m7g.large`）
- **ストレージ**：ルートディスクは通常 [[ebs]]。一時的な高速ディスクとして**インスタンスストア**が付くタイプもある

OS から上（パッチ適用、ミドルウェア、アプリ）は**利用者が管理**します。

## インスタンスタイプのファミリー

| 記号 | 種類 | 向いている用途 |
|---|---|---|
| T / M | 汎用（T はバースト可能） | Web サーバー、小〜中規模のアプリ |
| C | コンピューティング最適化 | バッチ処理、動画変換、科学計算 |
| R / X | メモリ最適化 | インメモリ DB、大規模キャッシュ |
| I / D | ストレージ最適化 | 高い IOPS が必要な DB、データウェアハウス |
| P / G | 高速コンピューティング（GPU） | 機械学習、グラフィックス |

## 購入オプション（コスト最適化で頻出）

| オプション | 割引 | 向いている使い方 |
|---|---|---|
| オンデマンド | なし | 短期間・予測できない負荷、まず試すとき |
| リザーブドインスタンス | 最大 72% 程度 | 1 年／3 年、ずっと動かし続けるサーバー |
| Savings Plans | 最大 72% 程度 | 1 年／3 年の利用額を約束。インスタンスタイプやリージョンを変えても割引が続く（Compute Savings Plans） |
| スポットインスタンス | 最大 90% 程度 | **中断されてもよい**処理（バッチ、分析、CI） |
| ハードウェア専有（Dedicated Hosts） | — | ソフトウェアのライセンスが物理サーバー単位のとき |

## 配置とネットワーク

- インスタンスは 1 つの **AZ** の 1 つのサブネットに置かれる。可用性を高めるには、複数の AZ に分けて [[elb]] と [[ec2-auto-scaling]] を組み合わせる
- **セキュリティグループ**：インスタンス単位のファイアウォール（ステートフル、許可ルールのみ）
- **Elastic IP**：固定のパブリック IP アドレス
- **プレイスメントグループ**：クラスター（同じラック近くに置いて低レイテンシー）、分散（別々のハードウェアに置いて障害の影響を分ける）、パーティション

## 試験でのポイント

- 「中断しても問題ない」「最もコスト効率が良い」→ **スポットインスタンス**
- 「24 時間 365 日、1 年以上動かす」→ **リザーブドインスタンス**か **Savings Plans**
- インスタンスに AWS の権限を渡すときは、アクセスキーを置かずに **IAM ロール（インスタンスプロファイル）** を使う
- インスタンスストアのデータは、インスタンスを**停止・終了すると消える**

## よくあるひっかけ

- スポットインスタンスは、AWS の都合で **2 分前の通知で中断**されることがある。止められない本番 DB には向かない
- セキュリティグループに「拒否」ルールは書けない。特定の IP を拒否したいなら**ネットワーク ACL** か [[waf]]
- サーバー管理を減らしたいという条件なら、EC2 より [[lambda]] や [[fargate]] が正解になりやすい
