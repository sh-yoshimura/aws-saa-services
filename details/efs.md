## しくみ

複数の [[ec2]] インスタンス（Linux）から、**NFS** プロトコルで同時にマウントできる共有ファイルシステムです。容量はファイルを置いた分だけ自動で増減し、事前の容量の確保は不要です。

- 標準では**複数の AZ**にデータを保存する（1 ゾーン型もある）
- 各 AZ に**マウントターゲット**を作り、そこへ接続する
- [[ecs]]、[[eks]]、[[lambda]] からもマウントできる
- オンプレミスからも [[direct-connect]] や VPN 経由でマウントできる

## ストレージクラスと性能

- **Standard**／**Infrequent Access（IA）**／**Archive**：ライフサイクル管理で、使われないファイルを安いクラスへ自動で移す
- スループットモード：**Elastic**（使った分だけ自動）、プロビジョンド（一定の性能を確保）、バースト

## 試験でのポイント

- 「複数のインスタンスから同じファイルにアクセスしたい」「Linux」「共有ストレージ」「容量が予測できない」→ EFS
- Auto Scaling で台数が変わる Web サーバー群の共有コンテンツ置き場として頻出
- コストを下げるには、ライフサイクル管理で IA クラスを使う

## よくあるひっかけ

- **Windows** のサーバーからは使えない（SMB 非対応）。Windows なら [[fsx]] for Windows File Server
- 1 台のインスタンスの高速なディスクが欲しいだけなら [[ebs]] のほうが合う
