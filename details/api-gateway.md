## しくみ

API の**窓口（玄関）**を作るサービスです。利用者（Web ブラウザ、スマホアプリ、他のシステム）からの HTTP リクエストを受け取り、認証や流量の制限をしたうえで、後ろにある処理（**バックエンド**）へ渡します。

- バックエンドの例：[[lambda]]、HTTP のエンドポイント（EC2・ALB・オンプレミスなど）、AWS のサービス（[[sqs]]、[[step-functions]]、[[dynamodb]] など）
- サーバーの管理は不要で、リクエスト数に応じて自動でスケールする
- 料金は、受け取ったリクエスト数（＋データ転送、キャッシュを使うならその時間料金）

API は次の部品で組み立てます。

| 部品 | 意味 | 例 |
|---|---|---|
| **リソース** | URL のパス | `/orders`、`/orders/{id}` |
| **メソッド** | HTTP の動詞 | `GET /orders`、`POST /orders` |
| **統合** | リクエストを渡すバックエンド | Lambda 関数、HTTP エンドポイント |
| **ステージ** | 公開する環境。URL に入る | `dev`、`prod`（`https://…/prod/orders`） |
| **デプロイ** | 設定をステージに反映する操作 | 変更してもデプロイするまで公開されない |

## API の種類（頻出）

| 項目 | REST API | HTTP API | WebSocket API |
|---|---|---|---|
| 向いている用途 | 機能を多く使いたい本格的な API | シンプルで**安く・速い** API | **双方向**のリアルタイム通信（チャット、通知、ゲーム） |
| 料金 | 高め | REST API より**大幅に安い** | 接続時間＋メッセージ数 |
| API キー・使用量プラン | ○ | ✕ | ✕ |
| キャッシュ | ○ | ✕ | ✕ |
| [[waf]] との連携 | ○ | ✕ | ✕ |
| リクエストの検証・変換 | ○ | 一部 | 一部 |
| 認証 | IAM、Cognito、Lambda オーソライザー | IAM、**JWT**（Cognito など）、Lambda オーソライザー | IAM、Lambda オーソライザー |
| プライベート API（VPC 内からだけ） | ○ | ✕ | ✕ |

**覚え方:** 「API キー」「使用量プラン」「キャッシュ」「WAF」「プライベート API」が要るなら **REST API**。それ以外で「低コスト」「低レイテンシー」なら **HTTP API**。

## エンドポイントの種類（REST API）

| 種類 | しくみ | 向いている場面 |
|---|---|---|
| **エッジ最適化** | [[cloudfront]] のエッジロケーションを経由して受け付ける（標準） | 世界中の利用者から呼ばれる API |
| **リージョン** | そのリージョンで直接受け付ける | 同じリージョンの利用者・システムから呼ばれる。自分で CloudFront を前に置きたいとき |
| **プライベート** | **VPC 内から**、インターフェイス型の [[vpc-endpoint]] 経由でだけ呼べる | 社内システム向けの API。インターネットに公開したくない |

## 統合の種類（バックエンドへのつなぎ方）

| 種類 | 内容 |
|---|---|
| **Lambda プロキシ統合** | リクエストをそのまま Lambda に渡し、Lambda の戻り値をそのまま返す。いちばんよく使う |
| HTTP 統合 | 公開されている HTTP エンドポイントに転送する |
| **AWS サービス統合** | Lambda を書かずに、SQS へのメッセージ送信、Step Functions の実行開始、DynamoDB への書き込みなどを直接行う |
| **VPC リンク** | VPC の**プライベートサブネット**にある NLB（HTTP API なら ALB・Cloud Map も）へつなぐ。バックエンドを公開せずに API にできる |
| モック | バックエンドなしで決まった応答を返す（テスト用） |

## 認証・アクセス制御

| 方法 | 使う場面 |
|---|---|
| **[[cognito]] ユーザープール**（REST）／**JWT オーソライザー**（HTTP） | アプリにログインした**利用者**だけに API を使わせる |
| **IAM 認証**（署名バージョン 4） | AWS の中のシステムや、IAM の権限を持つ人・ロールだけに使わせる |
| **Lambda オーソライザー** | 独自のトークンや外部の認証基盤など、**自分で書いたロジック**で判定する |
| **リソースポリシー**（REST） | 特定の **IP アドレス**・**VPC エンドポイント**・**AWS アカウント**からだけ呼べるようにする。プライベート API では必須 |
| 相互 TLS（mTLS） | クライアント証明書を持つ相手だけに使わせる（IoT、企業間の連携など） |

## 流量の制限と保護

- **スロットリング**：秒あたりのリクエスト数の上限。超えると **429 Too Many Requests** を返し、後ろのシステムを守る
  - アカウント全体（リージョンごと）：標準で毎秒 10,000 リクエスト＋バースト（上限は申請で引き上げ可能）
  - ステージ・メソッドごとにも上限を決められる
- **使用量プラン＋API キー**（REST）：利用者（顧客）ごとに、秒あたりのリクエスト数や**1日・1か月の呼び出し回数（クォータ）**を決める。API を有料で提供するときなどに使う
- **キャッシュ**（REST）：同じリクエストの応答をステージに保存し、指定した時間（TTL、標準 300 秒）はバックエンドを呼ばずに返す。バックエンドの負荷と応答時間を減らす
- [[waf]]（REST）：SQL インジェクションや特定の IP からのアクセスをブロック
- [[shield]] Standard：DDoS 攻撃から自動で保護（エッジ最適化なら CloudFront の保護も効く）

## 運用の機能

- **カスタムドメイン**：`api.example.com` のような独自のドメインで公開する。証明書は [[acm]]（エッジ最適化はバージニア北部 us-east-1、リージョンは同じリージョンで発行）
- **ステージ変数**：ステージごとに呼び出す Lambda のエイリアスなどを切り替える
- **カナリアリリース**（REST）：新しいデプロイに、リクエストの一部（例 10%）だけを流して確かめる
- **CORS**：別のドメインの Web ページから API を呼べるようにする設定
- **ログと監視**：アクセスログ・実行ログを [[cloudwatch]] Logs に送る。[[x-ray]] でリクエストを追跡する（REST）

## 主な制限（代表的な値）

| 項目 | 値 |
|---|---|
| 統合のタイムアウト | 標準 **29 秒**。リージョン・プライベートの REST API は、申請すれば 29 秒より長くできる（その代わり、アカウントのスロットリングの上限を下げることがある）。エッジ最適化の REST API と HTTP API は 29 秒まで |
| ペイロード（リクエスト・応答）のサイズ | **10 MB** まで |

最新の値は公式ドキュメント（API Gateway のクォータ）で確認してください。

## 試験でのポイント

- 「サーバーレスな REST API」→ **API Gateway ＋ Lambda ＋ DynamoDB** が定番
- 「急なアクセス増からバックエンドを守りたい」→ **スロットリング**
- 「API を顧客ごとのプランで提供し、呼び出し回数を制限」→ **使用量プラン＋API キー**（REST API）
- 「同じリクエストが多く、バックエンドの負荷を減らしたい」→ **API Gateway のキャッシュ**
- 「アプリの利用者を認証してから API を使わせたい」→ **Cognito ユーザープール**
- 「社内の VPC からだけ呼べる API にしたい」→ **プライベート API**＋インターフェイス型の VPC エンドポイント＋リソースポリシー
- 「プライベートサブネットのサービスを API として公開したい」→ **VPC リンク**＋NLB／ALB
- 「処理に時間がかかり、タイムアウトする」→ API Gateway から **[[sqs]] に直接送って**すぐ応答し、後ろで非同期に処理する（または [[step-functions]] を起動する）
- 「最もコストが低い、シンプルな API」→ **HTTP API**

## よくあるひっかけ

- **API キーだけでは認証にならない。** API キーは使用量プランで利用者を**識別**するためのもの。認証には IAM、Cognito、Lambda オーソライザーを使う
- **HTTP API には API キー・使用量プラン・キャッシュ・WAF がない。** 問題文にこれらが出たら REST API
- 長い処理を同期で待たせる設計は、タイムアウトの原因になる。「非同期」に変える選択肢を探す
- Lambda を HTTP で呼ぶだけなら、ALB（[[elb]]）や Lambda の関数 URL でもできる。**認証・流量制限・API キー・キャッシュ**などの API 管理の機能が必要なら API Gateway
- WebSocket が必要なのに REST API を選ぶのは誤り。サーバーから利用者へプッシュしたい双方向の通信は **WebSocket API**（GraphQL なら AWS AppSync）
