## しくみ

API の**窓口**を作るサービスです。利用者からのリクエストを受け取り、後ろにある [[lambda]]・HTTP エンドポイント・AWS のサービスへ渡します。サーバーレスで、リクエスト数に応じて自動でスケールします。

| API の種類 | 特徴 |
|---|---|
| REST API | 機能が多い（API キー、使用量プラン、リクエストの検証、キャッシュ、WAF 連携） |
| HTTP API | シンプルで**安く、速い**。JWT（Cognito など）認証 |
| WebSocket API | 双方向のリアルタイム通信（チャットなど） |

エンドポイントの種類：エッジ最適化（CloudFront 経由）、リージョン、プライベート（VPC 内からのみ）

## 主な機能

- **認証**：IAM、[[cognito]] ユーザープール、Lambda オーソライザー
- **スロットリング**：秒あたりのリクエスト数を制限して、後ろのシステムを守る
- **使用量プラン＋API キー**：利用者ごとに呼び出し回数を制限する
- **キャッシュ**：同じリクエストの応答を保存し、後ろの負荷を減らす（REST API）
- [[sqs]] や [[step-functions]] などに、Lambda を挟まず直接つなげる

## 試験でのポイント

- 「サーバーレスな REST API」→ **API Gateway ＋ Lambda ＋ DynamoDB** の組み合わせが定番
- 「急なアクセス増からバックエンドを守りたい」→ **スロットリング**
- 「API を有料プランで提供し、呼び出し回数を制限」→ **使用量プランと API キー**
- 「API の利用者を認証」→ Cognito ユーザープール

## よくあるひっかけ

- API キーだけでは**認証**にならない（使用量の識別用）。認証には IAM、Cognito、Lambda オーソライザーを使う
- 1 回のリクエストのタイムアウトは最大 29 秒程度（標準）。時間のかかる処理は非同期（SQS や Step Functions）にする
