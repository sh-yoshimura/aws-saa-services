## しくみ

Web アプリへの通信を検査し、攻撃と思われるリクエストをブロックする **Web アプリケーションファイアウォール**です。次のサービスの前に置きます。

- [[cloudfront]]、[[elb]]（ALB）、[[api-gateway]]、[[cognito]] ユーザープール、App Runner、AppSync

**Web ACL** という設定に、ルールを並べて使います。

## 主なルール

- **マネージドルール**：AWS やセキュリティ会社が用意したルールのセット（SQL インジェクション、XSS、既知の悪質な IP、ボットなど）
- **IP セット**：特定の IP アドレスを許可・拒否する
- **地域一致**：特定の国からのアクセスを許可・拒否する
- **レートベースルール**：同じ IP から 5 分間に一定回数を超えたらブロック（簡易的な DDoS・総当たり攻撃の対策）
- 文字列・正規表現、サイズ、ヘッダーなどの条件

## 試験でのポイント

- 「SQL インジェクション」「クロスサイトスクリプティング」「特定の国・IP をブロック」「L7 の攻撃」→ WAF
- 「1 つの IP から大量のリクエスト」→ **レートベースルール**
- 複数のアカウントに同じ WAF のルールを適用 → AWS Firewall Manager

## よくあるひっかけ

- WAF は EC2 インスタンスや NLB には直接付けられない（ALB や CloudFront の前で使う）
- 大規模な L3/L4 の DDoS 対策は [[shield]] の担当
