## しくみ

データを**メモリ上**に置くキャッシュ（一時的な保存場所）を、マネージドで提供します。データベースの前に置き、よく読まれるデータをキャッシュから返すことで、DB の負荷を減らして応答を速くします。

| エンジン | 特徴 |
|---|---|
| Redis OSS / Valkey | 複製・自動フェイルオーバー（マルチ AZ）、バックアップ、多様なデータ型（ランキング、Pub/Sub など） |
| Memcached | シンプル、マルチスレッド。複製やバックアップはない |

## キャッシュの使い方

- **遅延読み込み（Lazy Loading）**：キャッシュに無いときだけ DB から読み、キャッシュに入れる
- **書き込みスルー**：DB に書くときに、キャッシュにも書く
- **TTL**：古いデータが残り続けないように、期限を決める

## 試験でのポイント

- 「DB の読み取り負荷を下げたい」「同じクエリが何度も実行される」→ ElastiCache
- 「セッション情報を複数の Web サーバーで共有したい」→ ElastiCache（Redis）か [[dynamodb]]
- 「ゲームのランキング（リーダーボード）」→ Redis のソート済みセット
- 高可用性が必要 → **Redis**（Memcached は複製しない）

## よくあるひっかけ

- [[dynamodb]] のキャッシュなら、アプリの変更が少ない **DAX** のほうが適切
- キャッシュは導入にアプリ側の改修が必要。「アプリを変えずに読み取りを分散」なら RDS の**リードレプリカ**が候補
