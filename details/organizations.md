## しくみ

複数の AWS アカウントを**組織**としてまとめて管理します。

- **管理アカウント**（旧マスターアカウント）と**メンバーアカウント**
- **OU（組織単位）**：アカウントを部署・環境ごとにグループ分けし、階層を作る
- **一括請求**：請求をまとめ、利用量を合算して**ボリュームディスカウント**を受けられる。リザーブドインスタンスや Savings Plans の割引も共有できる
- 組織に新しいアカウントを API で作成できる

## SCP（サービスコントロールポリシー）（頻出）

OU やアカウントに付けて、**そのアカウントで使える権限の上限**を決めます。

- 例：「すべてのアカウントで、東京と大阪以外のリージョンを使わせない」「CloudTrail を停止させない」
- SCP は**権限を与えない**。実際に操作するには、IAM ポリシーでの許可も必要（両方で許可されたものだけができる）
- メンバーアカウントの**ルートユーザーにも効く**
- 管理アカウントには効かない

## その他のポリシーと連携

- **タグポリシー**、**バックアップポリシー**（[[backup]]）、AI サービスのオプトアウトポリシーなど
- [[cloudtrail]]、[[config]]、[[guardduty]]、[[security-hub]]、[[iam-identity-center]] などを組織全体で有効化できる

## 試験でのポイント

- 「複数のアカウントの請求をまとめたい」「割引を共有したい」→ Organizations の一括請求
- 「全アカウントで特定のサービス・リージョンの利用を禁止したい」「管理者でも変更できないように」→ **SCP**
- 新しくマルチアカウント環境をベストプラクティスに沿って作るなら [[control-tower]]

## よくあるひっかけ

- SCP で許可しても、IAM で許可していなければ操作できない。逆に IAM で許可していても、SCP で拒否されていればできない
