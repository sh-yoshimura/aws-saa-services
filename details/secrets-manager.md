## しくみ

データベースのパスワード、API キー、OAuth トークンなどの**秘密情報**を、暗号化して保存します（暗号化には [[kms]] を使う）。アプリは実行時に API で秘密情報を取得するので、コードや設定ファイルに書かなくて済みます。

- **自動ローテーション**：決めた間隔で、パスワードを自動で変更する
  - [[rds]]、[[aurora]]、[[redshift]]、[[documentdb]] は標準で対応
  - それ以外は [[lambda]] 関数でローテーションの処理を書く
- 秘密情報を別のリージョンに**複製**できる（災害対策）
- アクセスは IAM ポリシーとリソースポリシーで制御し、[[cloudtrail]] に記録される

## Parameter Store との違い

| 項目 | Secrets Manager | [[systems-manager]] Parameter Store |
|---|---|---|
| 自動ローテーション | **あり** | なし |
| 料金 | 秘密情報ごとの月額＋API 呼び出し | 標準パラメータは無料 |
| 向いているもの | DB のパスワードなどの秘密情報 | 設定値、ローテーション不要の秘密情報 |

## 試験でのポイント

- 「DB の認証情報を安全に保存し、**自動でローテーション**したい」→ Secrets Manager
- 「パスワードをコードにハードコードしない」→ Secrets Manager（ローテーション不要なら Parameter Store も可）

## よくあるひっかけ

- 「コストを最小に」「ローテーション不要」の設定値なら Parameter Store のほうが安い
